# Tripo run 2, 2026-08-31: the loop appears, and it proves the diagnosis

Hugo re-ran Tripo using one of the **gpt-image-2 generated images** as input,
rather than a product photograph. Files at `../runs-in/2026-08-31-tripo-run2/`,
rendered six ways at `../renders/band-run2-contact-sheet.jpg`.

## It made a closed loop

First correct topology in either run. The top view is a clean oval ring with a
real hole through it. The label is present as a small raised patch on the outer
face, blank rather than a mangled gold plaque. The weave reads as a faint grain.

## Why this one worked, and it is one variable

The input was a generated flat lay showing a peach band **lying open as an oval
on a surface, hole visible**, next to a drawstring pouch.

Every real product photograph in the workspace shows the band pressed FLAT, so
the hole is never visible and a flattened loop is the same picture as a strap.
Run 1 got straps. Run 2 got a loop. The only thing that changed is that the
input showed the hole.

**This validates `products/band-3d-shoot-list.md` before a single frame is
shot.** The shoot does not need to prove the method any more, only to supply the
real product.

## What is wrong with it

1. **The pouch bag came too.** The input image contained two objects and Tripo
   modelled both into one mesh, one primitive, one material. The bag has to be
   separated before anything else.
2. **The colour is invented.** Peach and salmon, from a generated image, not the
   measured product (D-027: LIGHT `#B8A080`, MEDIUM `#9D7459`, HEAVY `#6C4333`).
3. **1,986,674 triangles, 58.7MB, three 4096 maps.** A loop of this shape needs
   a couple of thousand triangles. This is roughly a thousand times over.
4. **The proportions are approximate.** Bounding box 0.920 x 0.461 x 0.980, so
   the band's width is about 0.48 of the loop's diameter. A real booty band sits
   nearer 0.33. It looks like a band; it is not this band.
5. **No real world scale**, though the origin does sit at the base (Y min is
   exactly 0), which is half the spec met and better than run 1.

## Two ways forward, and they are not exclusive

**A. Shoot the real band in this pose.** The shoot list stands, and the pose it
asks for is now proven to work. This is the honest route: real colour, real
weave, real label, real proportions, all reconstructed from the actual product.

**B. Keep this geometry and re-texture it.** A fabric loop is a generic shape,
so the geometry does not have to come from the real object. Separate the band
from the bag, decimate to a sane count, scale to measured millimetres, and drive
it with the real weave plates in `../../assets/textures/`, which are photographs
of the actual product.

On B, worth naming the parallel honestly: **D-034 rejected a texture transplant**
when the real weave was tiled over a generated band in a 2D poster, and Hugo
called it "that looks bad". This is a different operation. That was pasting
pixels over a photograph with no surface to sit on. This is applying a material
to UV mapped geometry, which is simply how product 3D is made. It may still fail
Hugo's eye, and his eye decides, but it should not be ruled out by the earlier
verdict.

Either way, **three measurements in millimetres are still needed**: width, flat
length, fabric thickness. Scale is the one thing no amount of processing
recovers.
