# Tripo run 1, 2026-08-31: what actually went wrong

Four outputs, all rejected. Hugo's read on sight was "very disappointing" and the
files agree, but the cause is not mainly Tripo.

## The four outputs

| File | Faces | Size | What it is |
|---|---|---|---|
| `tripo-brown-fabric-strap-a.glb` | 5,051 quads | 0.2 MB | untextured low poly preview |
| `tripo-brown-fabric-strap-b.glb` | 1,898,710 | 63.1 MB | flat brown strap, gold badge |
| `tripo-gold-sign-plaque.glb` | 1,919,233 | 57.1 MB | a standalone gold sign, no band at all |
| `tripo-leather-belt.glb` | 1,893,086 | 56.5 MB | flat leather strap, gold badge |

## 1. It was prompted, not photographed

The previews show the prompt used: **"brown fabric strap with metal label SPORTIF
HEAVY, featuring woven texture and stitching"** and **"brown fabric strap with
metal badge reading SPORTIF HEAVY"**, each against a single input thumbnail.

The S032 plan was different: upload the multi view plates from
`../products/band-reference-plates-v2/` (front flat, front folded, back, inside
grip, texture) because Tripo takes multiple images of one object. That did not
happen. These runs are text to 3D with one reference, which is the weakest mode
the tool has and the one furthest from our actual asset.

## 2. The prompt asked for the wrong object, and got it

Three words did most of the damage.

- **"strap"**. A strap is open. The band is a closed loop. Not one output is a
  loop, and it was never asked to make one. This is the S032 caveat about the
  hole being lumped closed, except the hole was never requested.
- **"metal label" / "metal badge"**. The real label is moulded into the fabric.
  Tripo did exactly as told and produced a gold metal plaque, which is why one
  entire run is a sign on its own with no band attached.
- **"leather"** appears nowhere in the prompt, yet one output is named and
  textured as a leather belt. Left to itself the model reaches for the nearest
  common object, and a brown strap with a metal buckle plate is a belt.

## 3. The label text is mangled, again

The plaque reads **HESVY**, not HEAVY, and the wireframe preview shows **eaif**.
Same failure as D-033 on the poster work: generators cannot render this label
reliably at any scale. Whatever route the mesh takes, the label is a separate
problem solved from the real photograph, not generated.

## 4. Every output fails the Shopify spec on the numbers alone

Target was GLB, about 4MB total, textures at or under 2048, real world scale,
origin centred at the product's base.

- **1.9 million triangles** on each textured output. A product AR asset wants
  tens of thousands. This is 20 to 40 times over.
- **56 to 63 MB** against a 4MB target, roughly 15 times over.
- **One 8192x8192 base colour map**, four times the linear cap.
- **Bounding box is exactly 2.000 x 2.000 x 2.000 on all four**, min at
  (-1, -1, -1). Every model is normalised into a unit cube. There is no real
  world scale at all, and the origin sits at the centre rather than the base.

That last one is worth reading twice. Even a perfect looking Tripo result would
arrive with no dimensions, which for a product a customer is judging the size of
is the one thing that cannot be wrong.

## The conclusion, and it closes the question rather than reopening it

A better prompt would fix points 1 and 2. It would not fix 3 or 4, and a
corrected run still lands as a two million triangle blob at no known size that
needs retopology, rescaling and re-texturing before it is usable.

Meanwhile the object itself is geometrically trivial: a closed loop with a flat
rectangular cross section. It is fully described by three measurements. Built
directly it comes out dimensionally exact, correctly scaled, low poly, and
textured from the weave plates in `../../assets/textures/`, which are real
photographs of the real product.

**Generation is the long way round to a worse result.** D-038 already established
that Lucy's friend's photos go through no generator; this is the same shape of
answer for a different reason. The mesh gets built, not generated.

## What is needed to build it

Three measurements off the physical band, in millimetres:

1. **Flat width** across the band.
2. **Flat length** laid flat, from folded end to folded end. The loop
   circumference is twice this.
3. **Thickness** of the fabric, doubled where it is a closed loop.

Plus, for the label: the moulded label's width and height, and where it sits
along the band.
